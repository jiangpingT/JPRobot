# 人形机器人训练复盘笔记

> 作者：阿策
> 项目：JPRobot — 人形机器人模块
> 最后更新：2026-02-27

---

## 总体目标

训练人形机器人（Gymnasium Humanoid 模型，MuJoCo 仿真）完成稳定双足行走。
验收标准：`ep_len > 500 步`（每步 0.01s，即至少撑 5 秒不摔倒，且在向前走）。

---

## 技术基础

| 参数 | 值 | 含义 |
|------|----|------|
| 物理引擎 | MuJoCo 3.5.0 | 比 PyBullet 更精确的接触动力学 |
| 观测空间 | 47 维 | qpos[2:](22) + qvel(23) + foot_contacts(2) |
| 动作空间 | 17 维 Box(-0.4, 0.4) | 17 个马达力矩 |
| FRAME_SKIP | 5 | 每个 env.step = 5 × 0.002s = 10ms |
| 存活判定 | 1.0m ≤ z ≤ 2.0m | 低于 1.0m = 摔倒，高于 2.0m = 弹飞 |
| 初始站立高度 | z = 1.4m | MuJoCo humanoid.xml 默认值 |
| 最大步数 | 1000 步 = 10 秒 | truncated（时间到）时不算失败 |
| PPO 配置 | net_arch=[256,256], lr=3e-4, batch=256 | 标准 SB3 配置 |
| 并行环境 | 8 (SubprocVecEnv) | M4 Pro 机器推荐值 |

## 迭代历史

### V1：基线（2026-02-26 完成）

**训练**：5M 步，约 15 分钟

**奖励函数**：
```
reward = +5.0 (存活) + 1.25 × vx (前进) - 0.1 × ||action||² (控制) - 0.5 × |y| (侧偏惩罚)
```

**结果**：
- 最佳奖励：613.4
- `ep_len` 稳定在 108~120 步（约 1.1 秒）
- 机器人能短暂平衡，但缓慢向前摔

**问题**：
- `ep_len` 远低于目标 500 步
- 侧偏惩罚 `-0.5 × |y|` 贡献负奖励，无实质改善

---

### V2：强化前进 + 步态奖励（2026-02-27，3.47M 步后放弃）

**改动**：
- `W_FORWARD`: 1.25 → 2.5（增强前进信号）
- `W_CTRL`: 0.1 → 0.05（允许更有力的动作）
- 去掉侧偏惩罚（`-0.5 × |y|`）
- 新增步态奖励：`1.0 × max(vx,0) × foot_contact_ratio`

**结果**：
- 3.47M 步时：奖励 798.9，`ep_len` 110~116
- 最佳奖励：877.7（但 ep_len 没有突破）

**诊断**（关键！）：

做了两个对照实验：
1. **零动作实验**：agent 什么都不做，机器人靠初始姿势撑 → 只撑 **40 步**就摔（z 从 1.4m 跌到 1.0m）
2. **V1 策略实验**：V1 训练好的策略 → 撑 **127 步**

结论：z 以约 0.003m/步 的速度缓慢下沉（重力）。V1/V2 的奖励函数没有给 agent 明确的"向上推"信号。Agent 虽然在努力平衡，但没有激励去主动蹬地抬高身体。

**根因**：奖励函数没有惩罚"缓慢下沉"，也没有奖励"踩地反弹"。

---

### V3：高度维持 + 交替步态（2026-02-27，进行中）

**改动**：
- 新增 `height_reward = 3.0 × max(0, (z - 1.0) / 0.4)`
  - z=1.0m（摔倒边界）时奖励=0，z=1.4m（完美站立）时奖励=3.0
  - **物理直觉**：直接对抗重力下沉，给 agent 明确的"往上撑"信号
- 步态奖励改为 `alternating_gait = 2.0 × |left_contact - right_contact| × max(vx,0)`
  - `|left_contact - right_contact|` = 1 只有当恰好一脚在地（标准行走步态）
  - 两脚同时落地（站立）= 0；两脚同时腾空 = 0
  - **物理直觉**：奖励"左脚→右脚→左脚"的真正行走步态，而非双脚站定不动
- 从 V2 best（或 V1 best）热启动

**完整奖励**：
```
reward = +5.0 (存活)
       + 2.5 × vx (前进)
       + 3.0 × (z-1.0)/0.4 (高度维持)
       + 2.0 × alternating × max(vx,0) (交替步态)
       - 0.05 × ||action||² (控制成本)
```

**训练配置**：10M 步，从 V2 best 热启动，ent_coef=0.01

**结果（2.3M 步后放弃）**：
- ep_len 仍卡在 130-152，每百万步仅增约 13 步
- 达到 500 步需约 27M 步 → 不可行
- 根因：47 维观测太窄，缺少身体动态感知（cvel+cfrc_ext）

---

### V4：扩展观测空间（2026-02-27，进行中）

**V3 根因分析**：
- 观测 47 维缺少两项关键感知：
  1. `cvel`（身体帧速度）：每个身体段在自身坐标系下的6DOF速度
     → 没有这个，agent 不知道"腰在往哪个方向倒"
  2. `cfrc_ext`（外部接触力）：每个身体段受到的地面反力
     → 没有这个，agent 不知道"脚踩地推力有多大"

**改动**：
- obs 维度：47 → 203（+cvel 78维 + cfrc_ext 78维）
- 奖励：完全复用 V3（高度维持+交替步态，无需修改）
- 从 SCRATCH 开始（obs 维度变化，V3 权重不兼容）

**训练配置**：15M 步，从零开始，ent_coef=0.01

**早期数据**（1M 步）：
- ep_len=82，增速约 35/百万步（V3 的 2.7 倍）
- 从零出发增长更快，预期可突破 V3 的 150 上限

**状态**：进行中（2026-02-27 启动，V3 在 2.3M 步时停止）

## 关键教训

### 1. 诊断先于改参

ep_len 卡住 → 不要乱改超参，先做对照实验：
- 零动作实验 → 量化"纯物理下沉速度"
- 旧策略回放 → 确认问题是奖励设计而非探索不够

### 2. 奖励函数要"堵死捷径"

与 Backflip v1 教训相同（见 CLAUDE.md）：
每项奖励都问"**agent 能不做 X 也拿到这个奖励吗？**"

V2 的步态奖励 `vx × foot_ratio` 有缺陷：
站着不动 foot_ratio=1，只要 vx 稍大就有奖励 → agent 可能学"迈一步后停住"

V3 的 alternating_gait 修复了这个问题：必须**持续**交替才有奖励。

### 3. 热启动可跨奖励函数

V1→V2→V3 的观测空间（47维）和动作空间（17维）完全相同。
`PPO.load(v2_best, env=v3_env)` 可以直接迁移策略网络权重，只有 critic 需要重新适应新奖励尺度。
这大大节省了从头探索的时间（热启动比随机初始化快 3-5 倍）。

### 4. 观测空间决定感知上限

奖励设计再好，如果 agent 感知不到关键物理量，就无法学会对应行为：
- 没有 `cvel`（身体帧速度）→ agent 无法感知"在哪个方向倒"
- 没有 `cfrc_ext`（接触力）→ agent 无法感知"脚踩地是否有效"
- V1/V2/V3 的 47 维观测只有关节角度+速度+二进制接触，感知太弱

Gymnasium Humanoid-v4 用 376 维观测，其中 cvel+cfrc_ext 就占 156 维。
V4 折中方案：在 47 维基础上加这两项 → 203 维。

### 5. 高度维持是双足的核心

四足机器人（Bittle）可以靠低重心稳定，双足人形没有这个选项。
如果没有明确的"保持高度"奖励，agent 会自然收敛到"矮身子缓慢爬行"的次优解。

## 下一步假设

如果 V3 的 ep_len 仍然无法突破（目标 >500 步），考虑：

**方案 A：扩展观测空间**
- 加入 `cfrc_ext`（外力传感）或身体帧速度（`body_xvelp`）
- 让 agent 更好地感知身体当前的运动状态

**方案 B：课程学习**
- 阶段 1：只训练保持站立（不强求前进）→ ep_len >500
- 阶段 2：加入前进奖励 → 在稳定站立基础上学走

**方案 C：脚踝/膝盖奖励**
- 明确奖励"膝盖弯曲后蹬直"的动作序列
- 量化膝关节角度变化，奖励类人步态的关节运动模式

**方案 D：使用 Gymnasium 原版 Humanoid-v5**
- 放弃自写 env，直接用经过验证的 Gymnasium 实现
- 376 维观测（含惯性矩阵、外力）可能对双足稳定至关重要
